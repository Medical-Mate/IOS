## 1. 제품 한 줄

진료실에서 하고 싶은 말을 미리 정리해 **브리핑 카드 한 장**으로 만들고, 진료가 끝나면
들은 말을 메모로 남겨 **소견 · 검사 · 약 · 재방문**으로 정리해 주는 앱.

## 2. 풀려는 문제

| 문제 | 증상 | 앱의 답 |
| -- | -- | -- |
| 진료실에서 말이 안 나온다 | 3분 진료, 긴장, 증상을 시간순으로 못 말함 | 사전 문답으로 증상을 구조화 → 카드 한 장 |
| 물어볼 것을 못 물어본다 | 나와서야 생각남 | AI 추천 질문 + 직접 추가(최대 5개)를 카드에 싣는다 |
| 들은 말을 잊는다 | 소견·약·검사·재방문 날짜가 섞여 기억에 안 남음 | 진료 직후 메모(글·음성) → AI가 축으로 분류해 저장 |
| 재방문을 놓친다 | "2주 뒤에 오세요"가 캘린더에 남지 않음 | 재방문 정보를 캘린더 일정으로 잇고 알림을 건다 |

## 3. 타깃 사용자

- 1차: 만성·반복 진료를 받는 성인 환자(본인 진료 준비).
- 2차: 보호자(향후). **현재 범위 밖** — 계정당 환자 1명이고 백엔드 `User` 식별자가
  `kakaoId` 단독이다.

## 4. iOS 트랙의 목표

1. Android MVP와 **기능 동등(feature parity)**. 같은 백엔드, 같은 Figma, 같은 화면 흐름.
2. iOS에서만 다른 것은 **구현 수단**이지 제품 사양이 아니다. 수단이 없어 기능을 줄여야
   하면 PRD를 고치고 결정 기록을 남긴다(→ `AOS-IOS-DIFF.md`).
3. iOS 네이티브 사용자 기대(제스처 뒤로가기, 공유 시트, 시스템 알림 권한 흐름)는 지키되,
   **디자인 토큰과 레이아웃은 Figma를 그대로 따른다.** 예쁘게 다듬지 않는다.

### 비목표 (이번 범위 아님)

- iPad · Mac Catalyst · Apple Watch 대응
- 다크 모드 (디자인 시스템에 다크 값이 없다)
- 다국어 (한국어 단일)
- 오프라인 전면 동작 (로컬 캐시 전략 미정, Android도 미정)
- 보호자 · 다계정 · 가족 공유

## 5. 성공 지표 (제안)

| 지표 | 정의 | 목표 |
| -- | -- | -- |
| 카드 완성률 | 증상 정리 시작 → 브리핑 카드 생성 비율 | 60% 이상 |
| 진료 후 기록률 | 진료 일정이 지난 카드 중 기록이 남은 비율 | 40% 이상 |
| 재방문 일정 전환률 | AI가 뽑은 재방문 중 사용자가 캘린더에 올린 비율 | 50% 이상 |
| 세션 중단 복귀율 | "이어서 하기"로 돌아와 끝낸 비율 | 30% 이상 |
| 크래시 프리 | 세션 기준 | 99.5% 이상 |

> 목표 수치는 iOS 트랙 제안값이다. 제품 트랙 합의 전까지 확정이 아니다.

## 6. 사용자 여정 (iOS에서도 동일)

```
설치
 └ 스플래시 → 카카오 로그인 → 온보딩 4장 → 신상정보 3단계(약·질환·알러지) → 홈
진료 전
 └ 홈 "증상 정리 시작하기"
     → 1단계 아픈 부위 고르기(3D 인체도)
     → 2단계 통증 강도(1~5)
     → 3단계 AI 문답(텍스트/음성) → 추천 질문 고르기(최대 5)
     → 브리핑 카드 생성 → 읽기 · 편집 · 진료받을 병원 지정 · 이미지 저장/공유
     → (선택) 캘린더에 진료 일정 잡기 + 진료 전 할 일
진료 당일
 └ 진료 전 알림 → 카드 다시 보기 → 진료실에서 카드 제시
진료 후
 └ 진료 후 기록 알림 → 병원 확인 → 메모(글·음성)
     → AI 분류(소견 · 검사 · 약 · 재방문 · 그 밖의 말) 확인 → 저장
     → 재방문이 있으면 사용자가 보고 캘린더 일정으로 올린다(자동 생성 아님)
돌아보기
 └ 기록 탭: 월별 목록 → 상세 타임라인(예정 · 진료 후 기록 · 카드)
```

## 7. 기능 범위 (MVP)

### 7.1 포함 — Android에 구현되어 있고 iOS도 해야 하는 것

| 영역 | 기능 | 비고 |
| -- | -- | -- |
| 진입 | 스플래시, 카카오 로그인, 서버 토큰 교환, 401 자동 재발급, 세션 복구 | |
| 온보딩 | 소개 4장, 신상정보 3단계(복용약 · 기저질환 · 알러지), 완료 모션 | |
| 증상 정리 | 3D 인체도 부위 선택(단일 선택) → 통증 강도(1~5) → AI 문답 → 추천 질문 선택/직접 추가 | 질문 최대 5개 |
| 음성 입력 | 문답·메모를 말로 입력. 1초 침묵이면 자동 전송, 5초 무음이면 패널 닫힘 | 기기 내 받아쓰기, 오디오 외부 전송 없음 |
| 음성 명령 | 호출어("헤이 메이트")로 패널을 띄우고 화면 이동 · 저장 등 명령 | iOS 구현 수단 재검토 대상 |
| 브리핑 카드 | 카드 읽기 · 전체 편집 · 진료받을 병원 지정 · 목록 · 삭제 · 이미지 저장/공유 | 확정 카드를 고치면 서버가 새 버전 생성 |
| 진료 후 기록 | 병원 확인 → 메모(글·음성) → AI 분류 결과 확인/수정 → 저장 | 저장 시 재방문 일정 흐름으로 연결 |
| 기록 | 월별 목록, 상세 타임라인(예정 · 기록 · 카드), 다중 삭제 | 같은 카드의 재방문이 한 화면에 쌓임 |
| 캘린더 | 월 화면 · 일자 화면 · 일정 추가/수정/삭제 · 진료 전 할 일 · 다가오는 일정 | |
| 알림 | 진료 전 알림 · 진료 후 기록 알림, 알림 시각 설정 | 로컬 알림 |
| 예약 문자 가져오기 | 병원 예약 문자를 공유하면 일정 추가 화면이 채워진 채 열림 | iOS는 Share Extension 필요 |
| 홈 | 상황별 배너(5장 순환), 이어서 하기(n/3), 최근 카드 2장, 다가오는 일정 | |
| 내 정보 | 건강 정보 요약/수정, 알림 설정, 온디바이스 처리 토글, 로그아웃, 회원탈퇴 | |
| 온디바이스 처리 | 켜면 메모 분류·문답 추출이 폰 안에서 동작(모델 다운로드 약 1.2GB) | iOS 대체 수단 결정 필요 |

### 7.2 제외 · 보류

| 항목 | 이유 |
| -- | -- |
| 진료실 전달 전용 화면(`handoff`) | IA에서 제외. 브리핑 카드를 그대로 보여준다 |
| Apple 로그인 · 전화번호 로그인 | 백엔드 미지원(`User` 식별자가 `kakaoId` 단독). **단, App Store 심사 리스크로 8장 참조** |
| 다크 모드 · 다이내믹 컬러 | 디자인 시스템에 값 없음 |
| 오픈소스 고지 화면 | Android도 미구현. 스토어 배포 전 필요(Pretendard OFL) |
| 로컬 DB 캐시 | 저장 전략 미정 |

## 8. iOS에서만 생기는 제품 리스크

| 리스크 | 내용 | 대응 |
| -- | -- | -- |
| **App Store 4.8 (Sign in with Apple)** | 제3자 소셜 로그인(카카오)만 제공하면 심사에서 Apple 로그인을 요구받을 수 있다 | 백엔드에 Apple 식별자 추가가 필요. **출시 전 결정 필수 항목**이며 백엔드 트랙과 협의해야 한다 |
| **의료 정보 앱 심사(1.4.1 / 5.1.1)** | 증상·약·알러지를 다루므로 개인정보 처리방침 URL, 데이터 수집 고지(App Privacy), 의료 자문 아님 고지가 필요 | 출시 전 체크리스트에 포함 |
| **온디바이스 모델 용량** | 약 1.24GB 다운로드. iOS는 앱 외부 다운로드 + 백그라운드 전송 정책을 지켜야 한다 | URLSession 백그라운드 다운로드, 셀룰러 차단, 저장공간 확인 |
| **호출어 상시 청취** | iOS는 백그라운드 상시 마이크가 사실상 불가하고, 앱 포그라운드에서도 배터리·권한 설명이 필요 | 포그라운드 한정 + 명시적 안내로 축소하거나 기능 보류 결정 필요 |
| **3D 인체도 자산** | Draco 압축 glTF를 쓰는 Filament 구현. iOS는 렌더러가 다르다 | 자산 변환 파이프라인 합의 필요(→ DIFF 문서 3장) |

## 9. 비기능 요구사항

| 항목 | 요구 |
| -- | -- |
| 최소 OS | **iOS 17.0 이상 (2026-11-20 확정)**. Android minSdk 26과 같은 "최근 2~3세대" 기준 |
| 화면 | iPhone 세로 전용. 디자인 캔버스 360×812pt 기준, 가로폭은 fill-width |
| 성능 | 3D 인체도 첫 프레임 2초 이내, 회전 60fps 목표 |
| 네트워크 | 모든 API 실패를 값으로 다루고 화면마다 오류/빈/로딩 상태를 그린다 |
| 보안 | 서버 JWT는 Keychain에만. iCloud 백업 제외. refresh TTL 30일 |
| 개인정보 | 음성 오디오는 기기 밖으로 내보내지 않는다. 메모 원문은 온디바이스 모드에서 외부 AI로 보내지 않는다 |
| 접근성 | VoiceOver 레이블, 최소 터치 44pt(Android 48dp 대응), Dynamic Type 대응 범위 결정 필요 |
| 품질 게이트 | 빌드 + 유닛 테스트 + 린트가 CI에서 강제. Android는 유닛 테스트 1,148건 |
